# Agent Note: 普通用户账号登录与实例授权

Status: implemented

## Problem

实例访问 Key 只能进入单个成员工作区，不适合一个人管理多个实例。管理员需要能创建、停用和重置普通账号，同时保留访问成员的渠道配置和记录。

## Decision

管理员和普通用户共用账号登录入口，管理操作仍要求管理员身份。普通账号通过访问成员关联实例：每个实例对同一个账号最多有一个成员，且一个成员只能交给一个账号。每次实例请求都核对当前授权，记录按访问成员隔离。schema 11 清除旧访客会话及旧访问 Key 的校验和密文数据，不修改已导入的渠道凭据。

管理员可在用户表单直接勾选实例，也可在实例的成员管理中只选择账号并确认绑定。首次授权自动创建成员，生成独立前缀并沿用实例的其余默认值。已有成员由单独的编辑入口调整，绑定弹窗不要求填写渠道设置。实例编辑表单只调整连接和启停状态。成员仍是历史记录与名称前缀的归属边界。

## Alternatives considered

- 并行保留访问 Key 可以减少切换时的中断，但用户明确不保留；统一登录也避免两套入口需要保持相同的授权规则。
- 账号直接关联实例能减少一层配置，但不能说明该用户应继承哪套渠道前缀和历史记录，故保留访问成员作为业务归属。

## Consequences

旧成员可由管理员绑定到正确的普通账号，也可从用户表单为尚无成员的账号授权实例并自动生成成员。改绑历史成员会让接收账号看到该成员的旧记录。停用账号或重置密码会撤销该账号的登录会话；撤销单个实例权限只停用对应成员，不影响其他实例。单实例导入的授权适用于[多目标推送](2026-11-22-channel-first-publishing.md)中的每一次实例请求。
