# Agent Note: 先填写渠道，再选择推送目标

Status: implemented

## Problem

实例工作区要用户先选实例，再填渠道。将一份配置发到多个实例时，每次都得重新录入 Key 和模型，容易填错，也看不到各台结果。

## Decision

独立的「新建渠道」先收集类型、Key 和模型，再选择已启用的授权实例和各自的分组。渠道配置共用；分组、渠道命名和记录归属仍由每个目标独立决定。页面依次调用原有单实例导入入口，逐台归纳进度和结果。每次请求继续采用[现有账号授权](2026-11-22-account-login.md)，不新增后端批量接口或数据表。

模型采用按渠道类型筛选的内置候选多选，并保留手动添加自定义模型。候选来源为本工具内置默认值，不宣称是供应商完整或实时模型目录；默认模型仍预选，最终列表继续通过现有模型校验。

## Alternatives considered

- 先选实例可以直接采用该台的模型默认值，但用户明确要先填渠道，且不能拿一台的分组或默认模型替代其他台。
- 服务器后台任务可以离开页面继续处理，但需要增加任务存储和 Key 生命周期；当前只要求在页面上确认一次并查看各台结果，复用单实例入口即可。

## Consequences

无需重复录入相同配置。每台机器的成功与失败独立，不做跨实例回滚。浏览器离开页面时停止提交后续目标，已发出的请求可能已经生效；网络中断未拿到完成事件时，不假定未创建，也不自动重试。
